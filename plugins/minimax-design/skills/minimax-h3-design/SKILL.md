# MiniMax H3 与 Design 创作

把创作目标转为可执行的制作方案，按实际入口交付提示词或操作 Design。默认用中文沟通；台词、字幕与画面文字保留用户要求的语言。

## 按任务读取参考

- 写 H3 提示词、参考素材、首尾帧、声音或视频编辑：[h3-guide.md](references/h3-guide.md)。
- 使用 Design、导出与资产复用、剪辑、导演台、本地 ComfyUI 工作流：[design-workflow.md](references/design-workflow.md)。
- 电商、KOC、教育、出海、动画或 AR 的创意结构和模板：[production-templates.md](references/production-templates.md)。
- 核对原文、入口、时效与未验证内容：[sources.md](references/sources.md)。

参考内容是 2026-10-16 从用户提供的两份手册提炼的快照。具体参数、支持入口、收费、部署要求与接口契约，以执行时的当前产品和官方资料为准。手册中的“推荐”“支持”不等于每次生成都能达到。

## 工作方式

1. **确定交付层级。** 区分提示词、分镜/制作方案、修改已有内容、实际操作平台。用户只要文案时直接交付文案；用户要求生成且有可用入口时继续执行。没有执行工具时，明确交付的是方案，不把文案当作已生成的视频，也不擅自换用其他模型。
2. **形成简报。** 从已有信息提取用途、受众、渠道、核心卖点/知识点、总时长、画幅、风格、目标语言、参考素材、必须保留的特征和声音需求。只询问会改变结果的缺项；其他低影响项给出合理假设，避免重复确认已明确的要求。产品卖点与知识内容须有依据。
3. **选择模式并核对素材。** 无素材用文生视频；需固定开头/结尾用首尾帧；需人物、动作、场景、音色组合参考或视频编辑用全能参考。区分输入素材时长、单次输出时长与最终成片时长。长片拆成适合单次生成的片段，再安排剪辑与声音衔接。
4. **写出能看见、能听见的内容。** 按“素材用途 → 核心创意 → 画面过程”组织提示词。引用编号与实际上传顺序一致；未上传素材不能假装已上传。每个镜头说明景别、主体、动作、运镜、台词和音效；台词长度匹配镜头时长，跨镜头对白标明延续关系。一镜到底用连续过程描述，避免混入切镜指令。
5. **按授权范围执行与修改。** 平台入口、参数字段、素材引用语法必须先核实。仅为做 skill 或写提示词，不启动付费生成、上传素材、发布社区或安装部署。用户已要求实际生成时按既有授权推进，不重复索取确认。修改时记录“保留什么 + 修改什么 + 为什么 + 期望结果”，围绕问题调整对应素材、镜头或音轨。
6. **验收并交付。** 有成片时实际查看画面、声音与输出规格，核对产品/人物一致性、字幕原文、台词、镜头衔接和渠道要求；教育视频还要核对事实和工序顺序。只有提示词时，检查引用、时长、台词与约束是否自洽，并明确尚未进行成片验收。

## 输出尺度

简单请求只给可复制的提示词，附必要的模式/素材说明。多镜头或商业项目按需提供：

- 简报与重要假设。
- 素材映射表：实际编号、文件/描述、用途、必须保持的特征。
- 分镜表：时间段、画面/运镜、台词/音效、素材引用。
- 可直接粘贴的 H3 或 Design 提示词，避免把解释性文字混入正文。
- 当前交付物、尚缺素材、实际验证结果与必要的下一步。

## 必须分清的边界

- H3 是模型能力；Design 是包含 Agent、画布、工具、资产与本地工作流的创作环境。Design 内的 Skill 与本目录的 Codex skill 是不同宿主的流程包，导入兼容性须核实。
- 本技能不提供未经验证的 API、CLI 或 MCP。网页功能名称不能直接推导成 API 参数；本地 ComfyUI 的引用语法也不能直接套用网页的 `@图片1`。
- 对长时间生成、下载或上传，遵循工作区的后台任务与独立监控要求。先验证可用执行/状态接口与跟进机制，再启动和交付查看方式；不以模型持续轮询代替监控，不把本地通知描述成已验证的自动模型介入。
- 不承诺积分赠送、免费运行、字幕完全可控、循环无缝或全片身份绝对一致。遇到实际问题保存任务 ID、使用的参数和可复现描述，按问题所在层修正。
